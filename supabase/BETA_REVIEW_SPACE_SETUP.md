# Beta review space 적용

## 추가된 탐색·비교 UX

- Team links에 공유 드라이브와 팀 GitHub를 연결합니다. 로그인 후 계정 창은 오른쪽 My page 패널로 열립니다. 로그인 및 이름 변경 동작은 유지합니다.
- 저장 버전은 바로 이전 저장 버전과 비교해 달라진 Common·Content Studio 항목을 강조합니다. 첫 버전과 Current approved Beta에는 비교 대상이 없다는 안내를 표시합니다.
- 항목을 선택하면 수정 전후 내용과 이전 버전들의 저장 내용을 표시합니다. Load earlier versions로 더 오래된 기록을 가져옵니다. 네덜란드어 비교에는 저장된 영어 대체 여부도 반영합니다.
- 과거 피드백은 같은 페이지·언어·과정·구조상 위치의 메모를 원문 인용과 함께 표시하고 원래 버전의 대화로 연결합니다. 기존 메모에는 영구적인 Studio 항목 ID가 없어 레이아웃이 바뀐 경우 원문 확인이 필요합니다. 과거 메모를 새 항목으로 재배정하지 않습니다.
- 이 추가 변경에는 별도 SQL이 필요하지 않습니다. 아래 검토 버전 SQL을 먼저 적용해야 합니다.

## 적용 순서

1. 기존 팀 관리 SQL까지 적용된 AI-Wise Supabase 프로젝트에서 `migrations/20260930184207_beta_review_versions.sql` 전체를 SQL Editor로 실행합니다.
2. 적용됐다고 알려주시면 테이블·함수·권한을 읽기 전용으로 확인한 후 Workspace를 배포합니다. 새 Secret이나 Edge Function은 필요 없습니다.
3. 관리자 계정으로 Beta를 열고 **New review version**에서 이름과 검토 내용을 입력합니다.
4. 버전을 선택하고 **Open preview**로 들어갑니다. 일반 멤버는 버전을 선택하고 피드백을 남길 수 있지만, 버전 생성은 관리자만 가능합니다.

## 저장 범위

- 수동으로 만든 검토 버전은 생성 시점의 Common Studio·Content Studio 콘텐츠를 복사합니다. 영어 원본 전체와 승인된 변경, 승인된 네덜란드어 콘텐츠가 포함됩니다. 승인 전 Studio 초안은 포함하지 않습니다.
- 복사는 한 데이터베이스 조회에서 수행되어 콘텐츠 중간 변경이 섞이지 않습니다. 저장 후에는 웹 클라이언트가 버전의 콘텐츠·제목·설명을 수정하거나 삭제할 수 없습니다.
- 이 기능은 **콘텐츠 검토 버전**입니다. GitHub 커밋, HTML/CSS/JavaScript, 영상·외부 모듈, Studio 편집 대상이 아닌 독립 활동 페이지를 보관하는 저장소 버전 기능은 아닙니다. 화면 구조는 현재 배포된 모듈을 사용합니다. 구조가 호환되지 않아 콘텐츠를 렌더링하지 못하면 해당 저장 버전의 피드백 작성을 차단합니다.
- 네덜란드어가 승인되지 않았던 부분은 그 버전의 저장된 영어를 표시하고 안내합니다.
- **Current approved Beta**는 계속 갱신되는 최신 승인 콘텐츠입니다. 기존 메모는 이 영역에 남고 새 버전으로 자동 복제되지 않습니다. 저장 버전의 메모와 최신 Beta의 메모는 서로 분리됩니다.
- 버전 선택 목록은 최근 200개를 표시합니다. 각 버전과 메모는 직접 연결되는 주소를 갖습니다.

## 피드백·언급

- `@` 입력 후 목록에서 팀원을 선택하면 해당 사람의 **Mentioned you** 목록에 메모/답글이 표시됩니다. 이메일이나 외부 알림은 전송하지 않습니다. 읽음/안 읽음 상태는 이번 범위에 포함되지 않습니다.
- 팀원 목록은 활성 계정의 이름과 내부 식별자만 제공합니다. 이메일 주소는 제공하지 않습니다. 중지된 계정은 언급 대상으로 저장할 수 없습니다.
- 작성자 식별자를 기준으로 메모·답글·미리보기 표시 색상을 일관되게 지정합니다. 이름과 번호도 함께 표시하므로 색만으로 사람을 구분하지 않습니다. 제한된 색상 팔레트여서 팀원이 많으면 색이 겹칠 수 있습니다.
- 기존 관리자 전용 해결/다시 열기 규칙과 일반 멤버의 Beta 전용 접근은 유지합니다.
- 새 필드는 기존 메모에 기본값을 추가합니다. 기존 댓글·답글·계정은 삭제하지 않습니다. 운영 계정이나 콘텐츠를 테스트 목적으로 변경하지 않습니다.

## 확인한 항목

- 임시 PostgreSQL: 관리자 전용 생성, 버전 불변성, 재시도 중복 방지, 언어별 저장 범위, 멤버 접근, 비회원/중지 계정 차단, 버전별 메모, 언급 대상 검증.
- DOM/서비스: 버전 페이지, 저장된 콘텐츠 렌더링, 로그아웃 및 권한 변경, 기존 Studio·언어·메모 회귀 검증.
- 가상 계정 브라우저: Account 묶음, 중앙 로그인, 모바일, 전체 페이지 미리보기, 버전 생성·선택, 댓글의 @자동완성과 언급 목록 이동, 하이라이트 커서.

운영 SQL 적용과 실제 계정 간 언급·버전 생성은 아직 별도 확인이 필요합니다. GitHub Pages 공개 호스팅 방식은 유지합니다. Supabase RLS는 저장된 검토 버전과 팀 피드백을 활성 팀원에게만 허용합니다.

운영 보안 진단의 기존 안내는 유지됐습니다: [비공개 감사 테이블의 정책 없음](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)은 의도된 클라이언트 접근 차단이며, [기존 workspace_role 실행 권한](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable), [유출 비밀번호 차단 설정](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)은 이번 변경에서 수정하지 않았습니다. 새 SQL 적용 후 별도 진단이 필요합니다.
