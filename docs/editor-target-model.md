# 편집 대상 정의와 기존 동작 대응표

이 정의는 현재 편집기를 공통 함수로 정리하기 위한 **검증용 모델**이다.
기존 대상을 어떻게 저장하고 편집하는지 설명하며, 새 저장 형식이나 새 권한을 도입하지 않는다.
운영 코드에는 연결하지 않았다. 기준 코드는 `766b85c`, 운영 기준점은 `c444116`이다.

## 분류 원칙

하나의 카테고리에 표시 모양, 저장 방식, 적용 범위를 모두 넣지 않는다.
예를 들어 제목이라는 역할만으로 공통 제목인지 예시별 제목인지, 서식이 가능한지 판단할 수 없다.
대상은 아래 속성의 조합으로 정의한다.

| 기준 | 분류 | 설명 |
|---|---|---|
| 값의 형태 | 텍스트, 선택값, 묶음, 목록 | 편집 가능한 값과 포함 관계. 서식 있는 텍스트도 텍스트에 속한다. |
| 역할 | 제목, 본문, 공통 라벨, 예시 카드, SAT 단계, 프롬프트 템플릿 등 | 실제 콘텐츠에서 맡는 역할. 역할만으로 기능을 허용하지 않는다. |
| 소유 범위 | 공통, 학과 | 현재 과목별 독립 콘텐츠 저장은 없다. 같은 학과의 과목들은 해당 학과 콘텐츠를 사용한다. |
| 배치 범위 | 슬롯, 예시, SAT 단계 | 예시별 박스는 학과 콘텐츠 안의 특정 예시에 속한다. 별도 소유 범위가 아니다. |
| 식별 방식 | 슬롯과 경로, 박스 ID, 순번과 대응표 | 기존 식별자를 그대로 사용한다. 분류 작업으로 ID를 새로 만들지 않는다. |
| 저장 방식 | 문자열, 문자열과 별도 서식, 박스 내부 서식 구간 | 공통 편집 함수에는 읽기·쓰기 연결부로 전달한다. |
| 표시 방식 | HTML, SVG, 속성, 페이지 제목, 맵 설명 원본, 과목 렌더러 | 서식 입력 허용과 실제 출력 지원을 구분한다. |
| 언어 규칙 | 언어별 문구, 공유 구조값 | 일반 문구는 각 언어에 남고 구조는 승인 후 동기화된다. 기존 예외는 아래에 명시한다. |
| 구조 변경 규칙 | 고정, 가변 | 목록이라는 이유만으로 추가·삭제할 수 있는 것은 아니다. |
| 기능 조건 | 설치된 기능, 언어 모드, 초안 상태, 제한값 | 대상 정의와 별도의 실행 조건이다. 표시되는 버튼과 실제 실행 조건을 함께 보존한다. |

`_studio.formats`는 다른 텍스트 대상을 꾸미는 서식 정보다. 독립된 본문으로 취급하지 않는다.
박스의 정렬·크기·앵커·ID·family도 본문이 아닌 구조 및 표시 정보다.

## 기존 대상과 규칙의 대응

| 기존 대상 | 형태와 소속 | 식별과 저장 | 현재 허용되는 동작과 예상 결과 |
|---|---|---|---|
| 일반 공통 제목·본문·표·목록·링크 문구 | 공통 텍스트, 원본 구조 고정 | `chapter.block-*` 또는 `chapter.extra-*`와 필드명; 문자열과 선택적 서식 | 문구 수정. 지원되는 HTML 텍스트는 서식 변경. 링크 문구 수정이 링크 주소 수정 권한을 뜻하지 않는다. |
| 세 예시 섹션의 공유 제목과 탐색 라벨 | 공통 텍스트, 여러 표시 위치가 하나의 원본을 참조 | 공통 라벨 슬롯의 필드 | 한 언어의 모든 참조 위치에 같은 변경이 적용된다. 카드별 본문과 별도 소유 관계다. |
| SAT 도식의 SVG 라벨 | 공통 텍스트 | 공통 슬롯의 SVG 텍스트 노드 | 문구 수정; 일반 HTML 서식 도구 제외. `<use>` 복사본은 같은 원본을 참조한다. |
| 접근성 설명과 페이지 제목 | 공통 텍스트 | `alt`, `title`, `aria-label`, `placeholder` 속성 또는 `<title>` | 문자열 수정; 인라인 서식 도구 제외. |
| 시스템 맵의 라벨·분류명·설명 | 공통 텍스트, 맵 원본 참조 | `[data-anatomy-copy]`의 기존 필드 | 기존 필드 편집. 분류명도 현재는 자유 텍스트다. HTML 원본의 서식 허용과 맵 표시 결과는 별도 계약이다. |
| C2 예시 카드 | 학과별 가변 목록, 카드 안에 텍스트 묶음 | `c2.examples[index]`; 제목·thinking·typing·processing·선택적 typing_note | 추가·복제·위아래 이동·삭제. 최소 1개, 최대 50개. 순서 변경 시 서식·박스 소속·언어 대응표도 따라간다. |
| What the model doesn’t know | 학과 콘텐츠의 예시별 텍스트 묶음 | 기존 `_studio.boxes` 안의 ID·family·example; 제목과 본문은 서식 구간 | 직접 입력·서식 변경. 박스가 없으면 최초 입력 때 생성한다. 열기만 할 때 저장 데이터를 만들지 않는다. 카드 복제·이동·삭제의 영향을 함께 받는다. |
| SAT 전체 예시 | 학과별 묶음: 단계 목록과 note | `c2.sat_example`; 제목은 별도 기존 슬롯 | 제목·note 편집, 단계별 편집 진입. 일반 예시 카드와 다른 기본 구성을 갖는다. |
| SAT 단계 | 학과 콘텐츠 안의 가변 목록 | `phases[index]`; 각 단계는 label과 정확히 4개 step | Self–AI 또는 Self–Team 단계 추가·삭제. 0~50개. 모든 step 본문이 비면 출력에서 숨기지만 저장 데이터는 유지한다. 단계 안의 4개 step은 고정이다. |
| actor와 AMD 결정값 | 의미를 가진 선택값 | SAT step의 actor, AMD 항목의 tag | 정해진 값 선택. 표시 문구 번역과 의미값 변경을 구분한다. |
| C3 프롬프트 비교·비평 문구 | 학과별 텍스트 또는 고정 묶음 | techniques의 bad/good, critique의 문자열 슬롯 | 기존 필드의 문구·서식 편집. 새 속성을 추가하는 기능은 없다. |
| C3 AMD 항목·Markdown·XML·전체 예시 | 학과별 고정 목록과 묶음 | 기존 배열 순번과 필드 경로 | 내부 제목·태그·문장 편집. 배열·줄의 추가·삭제 버튼은 없고 기존 검증기도 길이를 유지한다. XML tag의 언어 규칙은 아래 예외를 따른다. |
| 일반 추가 박스 | 공통 또는 학과 슬롯에 붙은 묶음; 예시에서는 특정 카드에 배치 | ID·slot·template·anchor, 예시의 경우 example·family | 입력·서식·복제·이동·삭제·정렬·크기. 이동은 같은 슬롯·템플릿·앵커·예시 그룹 안에서 이루어진다. 장 전체 박스 최대 50개. |
| 다른 예시에 있는 박스의 리마인더 | 편집 전용 표시, 현재 예시의 저장 대상은 아직 없음 | 원본 family와 예시 위치를 참조 | 추가를 선택하면 새 ID와 같은 family를 가진 독립 복사본 생성. 리마인더 자체는 학생용 콘텐츠로 저장하지 않는다. |
| 구형 Dutch 추가 박스 편집 | 같은 박스 데이터에 대한 호환 편집 모드 | 기존 박스 ID와 필드 순번 | 구조 동기화가 꺼진 공통 Dutch 경로에서 문구 편집과 번역 검토. 현재 입력 시 Undo 기록이 없는 동작도 유지 대상이다. |

일반 추가 박스는 `gradient-row`, `fn-card`, `dual-card`, `sl-card`, `text`의
5개 표시 템플릿을 지원한다. 현재 조사한 저장 자료에 있는 템플릿은 `gradient-row`와
`text` 두 종류지만, 나머지 세 종류의 지원을 삭제해서는 안 된다.

## 기능 조건은 데이터 카테고리와 분리

| 기능 | 현재 조건 |
|---|---|
| 일반 서식·추가 박스 도구 | blocks 기능 활성화, English 또는 양방향 구조 동기화 활성화. 공통 텍스트는 실제 출력 노드 종류도 확인한다. |
| 예시별 네 번째 섹션 | 위 조건에 example_boxes 활성화, 초안 차단 및 구조 충돌 없음, 새 박스 생성 시 50개 제한을 추가한다. |
| SAT 구조 변경 | blocks와 sat_phases 활성화, 초안 차단 없음. 구조 변경 실행 시 공통 충돌 검사도 통과해야 한다. |
| 구조 동기화 | 양방향 기능과 대응표가 유효할 때 승인 과정에 반영. 번역 문구를 구조값과 구분한다. |
| 저장·제출 | 기존 저장·복구·소스 검토·계정 조건을 그대로 사용한다. 대상 카테고리만으로 제출 허용을 판단하지 않는다. |

기존 기능에는 거절 시 이력을 기록하는 위치, 실행 전 확인하는 조건 등에 차이가 있다.
이를 하나의 조건으로 단순화해서 현재 동작을 바꾸지 않는다. 각 진입점의 조건을
재현한 후, 정책 변경이 필요하다면 별도 변경으로 다룬다.

## 단순한 일반 규칙으로 숨기면 안 되는 기존 차이

1. **XML tag는 자유 입력이지만 공유 구조값이다.** 입력창은 일반 텍스트이고,
   구조 동기화는 `tag`라는 키를 언어 공통 값으로 처리한다. AMD tag만의 규칙이 아니다.
   따라서 “입력창이 텍스트이면 언어별 문구”라는 규칙은 현재 구현을 설명하지 못한다.
2. **네 번째 섹션은 전용 저장 형식이 아니다.** 일반 박스 형식과 semantic family를
   사용한다. 오래된 자료는 영어 제목으로도 인식하고, example이 없으면 첫 예시로 본다.
   같은 예시에 여러 후보가 있으면 처음 찾은 항목만 전용 섹션으로 취급한다.
3. **네 번째 섹션의 직접 동작과 상위 카드 동작은 다르다.** 직접 편집창에는 제목·본문
   서식 도구가 있으며, 일반 박스처럼 삭제·이동 버튼이 노출되지는 않는다.
   상위 카드의 복제·이동·삭제에는 함께 반영된다.
4. **서식 도구 노출과 표시 결과가 동일한 개념은 아니다.** 맵 설명은 숨겨진 HTML
   원본에서 읽혀 표시된다. 이 원본은 현재 서식 도구 조건을 통과하지만, 모든 서식이
   맵 출력에 반영된다는 보장은 없다. 과목 서식 렌더러도 일부 경로는 문자열 검색을 사용한다.
5. **현재 식별자는 모두 안정 ID인 것이 아니다.** 공통 블록·필드 이름, 배열 순번,
   DOM 템플릿 앵커도 식별에 쓰인다. 분류 단계에서 이를 교체하면 기존 초안 복구가 깨질 수 있다.
6. **역할 선택값의 호환 범위가 다르다.** 일반 검증기는 과거 actor `student`도 고려하지만
   현재 선택창은 self/ai/team을 제공한다. SAT 전용 검증기는 3개 값만 허용한다.
7. **구형 번역 입력은 Undo 이력을 만들지 않는다.** 새 모델이 이 차이를 설명할 수 있어야
   한다. 기록을 추가하는 것은 리팩터링과 분리된 동작 개선이다.

## 검증과 다음 구현 경계

`checks/editor-target-audit.cjs`는 현재 소스의 공통 카탈로그·과목 슬롯·학과 원본과
승인본에서 대상을 수집한다. 알 수 없는 슬롯·템플릿·필드, 잘못된 확장 데이터는
조사 결과에 문제로 남긴다. `--details`를 주면 모든 대상의 기존 식별 경로와 정의를 출력한다.
파일을 수정하거나 저장 데이터를 새 정의로 변환하지 않는다.

`workspace/tests/editor-target-audit.test.cjs`는 다음을 검증한다.

- 조사 대상의 정의 연결, 식별 중복 및 원본 바이트 보존.
- 공통 원본 879개 필드에서 정의가 예측한 서식 허용 여부와 실제 편집 함수의 도구 노출 일치.

- XML tag의 공유 규칙, SAT 역할과 단계명의 서로 다른 언어 규칙.
- 구형·번역된 네 번째 섹션의 식별과 예시 소속 보존.

새 점검 5개를 포함한 전체 64개 테스트 파일이 통과했다.

이 검증은 **기존 자료를 분류할 수 있고 선택한 동작 규칙이 현재 구현과 일치한다**는
근거다. 전체 편집기를 새 대상 정의로 교체했다거나 모든 사용자 상태를 재현했다는 뜻은 아니다.
다음 구현에서는 이 대응표의 규칙을 대상 정의로 옮기고 `panel`, `unknownPanel`,
`satPanel`이 정의를 읽도록 전환한다. 기존 저장 형식, ID, 검토 상태와 원본은 유지한다.

먼저 본문 값 변경과 박스 생성 규칙을 연결하고, 이후 목록 구조 변경을 연결한다.
단계마다 같은 동작을 기존 구현과 새 구현에 실행해 값·서식·이력·언어 대응표·제출 데이터를
비교한다. 위에 적은 기존 차이는 그 비교의 명시적인 기대 결과로 남긴다.
